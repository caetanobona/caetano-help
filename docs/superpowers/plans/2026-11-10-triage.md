# Support triage demo implementation plan

> **For agentic workers:** Use superpowers:executing-plans to implement task by task.

**Goal:** Complete the credential-free portfolio demo in CLOUD_TASK.md.
**Architecture:** A pure deterministic triage function retrieves curated fictional runbook excerpts, returns category/route/action/source references, and formats a Slack thread response. The signed Worker schedules the bounded Slack API call after ACK. No LLM or new runtime dependency; no persistent state or deduplication.
**Tech stack:** TypeScript, Cloudflare Workers, existing Vitest/workerd.
**Spec:** CLOUD_TASK.md (owner authorized autonomous Go execution).

## Global constraints
Fictional data only. Preserve HMAC validation. No live deploy, Slack messages, paid APIs, or credentials. Existing checkout; no worktree.

## Review focus
- Conflicting categories must clarify rather than guess.
- Unknown evidence must never invent remediation.
- Malformed signed payloads must not crash or post.
- Slack errors must not leak user content or credentials in logs.
- Duplicate deliveries and post-ACK failures have explicit best-effort semantics.
